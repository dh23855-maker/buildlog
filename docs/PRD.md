# BuildLog 제품 요구사항 문서(PRD)

## 1. 문서 목적

이 문서는 BuildLog의 첫 번째 버전에서 무엇을 만들어야 하는지 쉽게 설명하는 제작 주문서입니다.

`MVP.md`에서 확정한 기능과 이후 대화에서 확정한 세부 규칙을 빠짐없이 포함합니다.

## 2. 서비스 소개

BuildLog는 공부와 프로젝트 기록을 한곳에 모아두는 웹사이트입니다.

사용자는 오늘 공부한 내용, 앞으로 해야 할 일, 오류와 해결 방법을 기록할 수 있습니다. 저장한 내용은 나중에 목록과 검색을 통해 다시 찾아볼 수 있습니다.

컴퓨터와 휴대폰 브라우저에서 모두 편하게 사용할 수 있는 반응형 웹사이트로 만듭니다.

## 3. 누가 사용하는 서비스인가요?

- 오늘 무엇을 공부했는지 기록하고 싶은 사람
- 공부 계획이나 프로젝트의 할 일을 관리하고 싶은 사람
- 오류와 해결 방법을 기록해 비슷한 문제가 생겼을 때 다시 찾아보고 싶은 사람
- 자신의 기록을 다른 사용자와 공유하고 싶은 사람

BuildLog는 여러 사용자가 회원가입해서 사용하는 서비스입니다. 각 사용자는 자신의 비공개 기록을 다른 사람과 분리해서 관리합니다.

## 4. 어떤 불편을 해결하려고 하나요?

사용자는 공부와 문제 해결 내용을 메모장, AI 대화, 여러 문서에 나누어 기록합니다. 시간이 지나면 어디에 적었는지 기억하기 어렵고, 이전에 해결한 오류도 다시 찾기 어렵습니다.

또한 앞으로 해야 할 일을 따로 관리하지 않으면 무엇을 끝냈고 무엇이 남았는지 알기 어렵습니다.

BuildLog는 다음과 같이 이 불편을 줄입니다.

- 공부 기록, 할 일, 오류 기록을 한곳에 저장합니다.
- 저장한 기록을 목록과 검색으로 다시 찾습니다.
- 할 일의 완료 여부와 오류의 해결 여부를 구분합니다.
- 비공개 기록은 본인만 보고, 원하는 기록은 다른 사용자에게 공개합니다.

## 5. 사용자가 각 기능으로 무엇을 할 수 있나요?

### 5.1 회원가입과 로그인

#### 회원가입

- 사용자는 이메일, 비밀번호, 닉네임을 입력해 가입할 수 있습니다.
- 닉네임은 다른 사용자와 겹칠 수 없습니다.
- 사용자는 가입 후 자신의 닉네임을 변경할 수 있습니다.

#### 로그인

- 사용자는 가입한 이메일과 비밀번호로 로그인할 수 있습니다.
- 로그인한 사용자는 자신의 기록을 만들고 관리할 수 있습니다.
- 다른 사용자의 비공개 기록은 볼 수 없습니다.
- 사용자는 로그아웃할 수 있습니다. 여러 사람이 함께 쓰는 컴퓨터에서도 안전하게 사용하기 위해서입니다.

#### 첫 버전에 포함하지 않는 회원 기능

- 이메일 확인
- 비밀번호 찾기

### 5.2 기록의 공개와 비공개

- 공부 기록, 할 일, 오류 기록은 처음 만들 때 기본적으로 비공개입니다.
- 비공개 기록은 작성자 본인만 볼 수 있습니다.
- 작성자는 원하는 기록을 공개로 설정할 수 있습니다.
- 공개 기록은 로그인한 다른 사용자가 볼 수 있습니다.
- 로그인하지 않은 사람은 공개 기록을 볼 수 없습니다.

### 5.3 공부 기록

사용자는 오늘 공부하거나 작업한 내용을 기록합니다.

#### 입력하고 저장하는 정보

| 항목 | 기준 |
| --- | --- |
| 제목 | 1~100자 |
| 내용 | 1~5,000자 |
| 공개 여부 | 기본값은 비공개이며 공개로 변경 가능 |
| 작성 날짜와 시간 | 기록을 만들 때 자동 저장 |

#### 사용자가 할 수 있는 일

- 공부 기록 만들기
- 내가 작성한 공부 기록 목록 보기
- 공부 기록 자세히 읽기
- 공부 기록 수정하기
- 공부 기록 삭제하기
- 공개 또는 비공개로 바꾸기
- 내 공부 기록을 제목과 내용으로 검색하기
- 공개된 공부 기록 검색하기

#### 목록 기준

- 최근에 작성한 공부 기록부터 보여줍니다.

### 5.4 할 일

사용자는 앞으로 공부할 내용이나 프로젝트에서 해야 할 일을 기록합니다.

예: `저장 버튼 만들기`, `파이썬 복습하기`

#### 입력하고 저장하는 정보

| 항목 | 기준 |
| --- | --- |
| 제목 | 1~100자 |
| 완료 여부 | 미완료 또는 완료 |
| 공개 여부 | 기본값은 비공개이며 공개로 변경 가능 |
| 완료 날짜와 시간 | 완료로 체크할 때 자동 저장 |

#### 사용자가 할 수 있는 일

- 할 일 만들기
- 할 일을 완료로 체크하기
- 할 일 수정하기
- 할 일 삭제하기
- 공개 또는 비공개로 바꾸기
- `전체`, `남은 일`, `완료한 일`로 나누어 보기

#### 목록 기준

- 완료하지 않은 할 일을 먼저 보여줍니다.
- 같은 완료 상태에서는 최근에 작성한 할 일부터 보여줍니다.

### 5.5 오류 기록

사용자는 오류가 생겼을 때 오류 내용과 해결 과정을 기록합니다. 아직 해결하지 못한 오류도 먼저 저장할 수 있습니다.

#### 입력하고 저장하는 정보

| 항목 | 기준 |
| --- | --- |
| 오류 제목 | 1~100자 |
| 오류 내용 | 1~5,000자 |
| 해결 방법 | 해결 전에는 비워둘 수 있음. 입력할 때는 1~5,000자 |
| 해결 여부 | 미해결 또는 해결 |
| 공개 여부 | 기본값은 비공개이며 공개로 변경 가능 |
| 해결 날짜와 시간 | 해결 상태로 바꿀 때 자동 저장 |

#### 사용자가 할 수 있는 일

- 오류 기록 만들기
- 미해결 상태로 저장하기
- 해결한 뒤 해결 방법 작성하기
- 해결 여부 바꾸기
- 오류 기록 수정하기
- 오류 기록 삭제하기
- 공개 또는 비공개로 바꾸기
- `전체`, `미해결`, `해결`로 나누어 보기
- 내 오류 기록을 제목과 내용으로 검색하기

#### 목록 기준

- 최근에 작성한 오류 기록부터 보여줍니다.
- 오류를 해결 상태로 바꾸려면 해결 방법을 반드시 입력해야 합니다.

### 5.6 공개 기록

- 사용자는 공개로 설정된 기록을 모아볼 수 있습니다.
- 공개 기록 화면에는 공부 기록, 할 일, 오류 기록을 모두 보여줍니다.
- 사용자는 공개 기록을 공부 기록, 할 일, 오류 기록으로 나누어 볼 수 있습니다.
- 공개된 공부 기록, 할 일, 오류 기록을 검색할 수 있습니다.

### 5.7 댓글과 좋아요

- 공개된 공부 기록과 오류 기록에는 댓글과 좋아요 기능을 제공합니다.
- 공개된 할 일에는 댓글과 좋아요 기능을 제공하지 않습니다.
- 댓글은 1~500자로 입력합니다.
- 첫 버전에서는 댓글에 답글을 다는 기능을 제공하지 않습니다.
- 댓글 작성자는 자신의 댓글을 수정하고 삭제할 수 있습니다.
- 기록 작성자는 자신의 공개 기록에 달린 댓글을 삭제할 수 있습니다.
- 한 사용자는 같은 기록에 좋아요를 한 번만 누를 수 있습니다.
- 좋아요를 다시 누르면 좋아요가 취소됩니다.

### 5.8 신고

- 로그인한 사용자는 공개 기록이나 댓글을 신고할 수 있습니다.
- 신고한 내용은 운영자가 확인할 수 있도록 저장합니다.
- 신고되었다는 이유만으로 기록이나 댓글을 자동으로 삭제하지 않습니다.

### 5.9 검색

첫 버전에서 확정된 검색 범위는 다음과 같습니다.

- 내 공부 기록: 제목과 내용으로 검색
- 내 오류 기록: 제목과 내용으로 검색
- 공개 공부 기록: 검색 가능
- 공개된 할 일: 검색 가능
- 공개된 오류 기록: 검색 가능

내 할 일 검색은 첫 버전에 포함하지 않습니다.

## 6. 어떤 화면이 필요한가요?

정확한 색상과 화면 모양은 아직 정하지 않았습니다. 첫 버전에는 다음 화면이 필요합니다.

### 6.1 회원가입 화면

- 이메일, 비밀번호, 닉네임을 입력합니다.
- 회원가입을 요청합니다.

### 6.2 로그인 화면

- 이메일과 비밀번호를 입력합니다.
- 로그인을 요청합니다.

### 6.3 내 기록 홈 화면

- 사용자가 자신의 공부 기록, 할 일, 오류 기록으로 이동할 수 있습니다.
- 밝은 배경과 읽기 쉬운 카드 형태로 핵심 기록을 보여줍니다.
- 메뉴의 이름과 위치를 분명하게 표시합니다.
- 사용자는 계정 설정에서 자신의 닉네임을 변경할 수 있습니다.

### 6.4 공부 기록 화면

- 공부 기록 목록을 봅니다.
- 공부 기록을 작성합니다.
- 공부 기록의 자세한 내용을 읽습니다.
- 공부 기록을 수정하거나 삭제합니다.
- 내 공부 기록을 검색합니다.

### 6.5 할 일 화면

- 할 일 목록을 봅니다.
- 할 일을 작성합니다.
- 완료 여부를 바꿉니다.
- 할 일을 수정하거나 삭제합니다.
- 전체, 남은 일, 완료한 일을 나누어 봅니다.

### 6.6 오류 기록 화면

- 오류 기록 목록을 봅니다.
- 오류 기록을 작성합니다.
- 오류 기록의 자세한 내용을 읽습니다.
- 해결 여부와 해결 방법을 기록합니다.
- 오류 기록을 수정하거나 삭제합니다.
- 전체, 미해결, 해결 상태로 나누어 봅니다.
- 내 오류 기록을 검색합니다.

### 6.7 공개 기록 화면

- 다른 사용자가 공개한 공부 기록, 할 일, 오류 기록을 봅니다.
- 기록 종류별로 나누어 볼 수 있습니다.
- 공개된 공부 기록, 할 일, 오류 기록을 검색합니다.
- 공개된 공부 기록과 오류 기록에 댓글과 좋아요를 사용합니다.
- 공개 기록이나 댓글을 신고할 수 있습니다.

### 6.8 반응형 화면

- 모든 주요 화면은 컴퓨터와 휴대폰 브라우저에서 사용할 수 있어야 합니다.
- 화면 크기에 맞게 내용이 읽기 쉽게 정리되어야 합니다.

## 7. 어디까지 되면 첫 버전이 완성된 것인가요?

다음 항목을 모두 확인하면 첫 버전의 핵심 기능이 완성된 것으로 판단합니다.

- [ ] 사용자가 이메일, 비밀번호, 닉네임으로 회원가입할 수 있습니다.
- [ ] 닉네임은 중복되지 않으며 사용자가 나중에 변경할 수 있습니다.
- [ ] 사용자가 이메일과 비밀번호로 로그인하고 로그아웃할 수 있습니다.
- [ ] 사용자마다 자신의 비공개 기록이 분리되어 있습니다.
- [ ] 다른 사용자는 비공개 기록을 볼 수 없습니다.
- [ ] 공부 기록을 만들고, 목록에서 찾고, 읽고, 수정하고, 삭제할 수 있습니다.
- [ ] 내 공부 기록과 공개 공부 기록을 검색할 수 있습니다.
- [ ] 할 일을 만들고, 완료 여부를 바꾸고, 수정하고, 삭제할 수 있습니다.
- [ ] 할 일을 전체, 남은 일, 완료한 일로 나누어 볼 수 있습니다.
- [ ] 오류를 미해결 상태로 저장할 수 있습니다.
- [ ] 해결 방법을 입력해야 오류를 해결 상태로 바꿀 수 있습니다.
- [ ] 오류 기록을 읽고, 수정하고, 삭제할 수 있습니다.
- [ ] 오류 기록을 전체, 미해결, 해결 상태로 나누어 볼 수 있습니다.
- [ ] 내 오류 기록을 제목과 내용으로 검색할 수 있습니다.
- [ ] 세 종류의 기록이 기본적으로 비공개로 저장됩니다.
- [ ] 사용자가 원하는 기록을 공개로 바꿀 수 있습니다.
- [ ] 로그인한 사용자는 다른 사용자의 공개 기록을 볼 수 있고, 로그인하지 않은 사람은 볼 수 없습니다.
- [ ] 공개된 공부 기록, 할 일, 오류 기록을 모아보고 종류별로 나누어 볼 수 있습니다.
- [ ] 공개된 공부 기록, 할 일, 오류 기록을 검색할 수 있습니다.
- [ ] 공개된 공부 기록과 오류 기록에서 1~500자의 댓글을 작성할 수 있습니다.
- [ ] 댓글 작성자는 자신의 댓글을 수정·삭제할 수 있고, 기록 작성자는 자신의 기록에 달린 댓글을 삭제할 수 있습니다.
- [ ] 한 사용자가 기록 하나에 좋아요를 한 번만 누를 수 있고 다시 누르면 취소됩니다.
- [ ] 로그인한 사용자가 공개 기록이나 댓글을 신고할 수 있습니다.
- [ ] 할 일 완료 날짜와 오류 해결 날짜가 자동으로 저장됩니다.
- [ ] 공부 기록 작성 날짜와 시간이 자동으로 저장됩니다.
- [ ] 컴퓨터와 휴대폰에서 주요 기능을 사용할 수 있습니다.

## 8. 이번에 만들지 않는 기능

- 이메일 확인
- 비밀번호 찾기
- 할 일 마감일
- 할 일 중요도
- 내 할 일 검색
- 댓글 답글

## 9. 화면 디자인 원칙

- 밝은 배경을 사용합니다.
- 목록과 기록은 읽기 쉬운 카드 형태로 보여줍니다.
- 메뉴와 버튼의 이름을 처음 사용하는 사람도 이해하기 쉽게 작성합니다.
- 컴퓨터와 휴대폰에서 모두 사용할 수 있는 반응형 화면으로 만듭니다.
- 화려한 효과보다 기록을 쉽게 작성하고 찾는 데 집중합니다.

## 10. 개발 기술

처음 개발하고 관리하기 쉬운 구성을 사용합니다.

| 구분 | 사용할 기술 | 선택 이유 |
| --- | --- | --- |
| 화면 | React | 버튼, 목록, 입력칸 같은 화면 조각을 나누어 만들고 다시 쓰기 쉬움 |
| 서버 | Python, FastAPI | 화면이 요청하는 기능을 간단한 코드로 만들고, 입력값 검사를 기본으로 지원함 |
| 데이터베이스 (실제 서비스) | Supabase | 데이터베이스 서버를 직접 설치·관리하지 않고 인터넷에서 사용할 수 있음 |
| 데이터베이스 (개발·테스트) | SQLite | 별도 설치 없이 내 컴퓨터에서 파일 하나로 바로 시험해 볼 수 있음 |

- 개발과 자동 테스트는 SQLite로 먼저 진행하고, 기능이 완성되면 Supabase에 연결합니다.
- 같은 코드가 SQLite와 Supabase 양쪽에서 똑같이 동작하도록, 한쪽에서만 되는 데이터베이스 기능은 사용하지 않습니다.
- 정확한 버전은 개발을 시작할 때 서로 호환되는 안정 버전으로 정합니다.

## 11. 아직 정하지 않은 내용

첫 MVP의 기능 범위와 기본 동작은 모두 정했습니다. 구현 중 새로운 기능이 필요해져도 임의로 추가하지 않고 별도로 결정합니다.

## 12. 확장 기능: 비공개 학습 자료함 (2026-10-27 추가)

첫 버전(1~11장)에 더해, 배운 순간의 캡처와 실습 영상을 모아두는 **비공개 학습 자료함**을 추가합니다. 1~11장의 내용은 바꾸지 않고, 이 장은 그 뒤에 덧붙이는 확장입니다. 8장의 "이번에 만들지 않는 기능" 목록은 그대로이며 학습 자료함과 겹치지 않습니다.

### 12.1 왜 필요한가요?

- 공부하며 찍은 화면 캡처와 실습 영상은 글 기록만으로는 남기기 어렵습니다.
- 자료를 한곳에 모아 두면 나중에 복습할 때 다시 찾아보기 쉽습니다.

### 12.2 사용자가 할 수 있는 것

- 제목, 선택 메모, 파일 한 개를 올려 자료를 등록할 수 있습니다.
- 내가 올린 자료를 최신순 목록으로 볼 수 있고, 이미지와 영상으로 나누어 볼 수 있습니다.
- 자료의 원본(이미지 또는 영상)을 열어 볼 수 있습니다.
- 내 자료를 삭제할 수 있습니다.

### 12.3 규칙

| 항목 | 규칙 |
| --- | --- |
| 공개 범위 | 항상 비공개입니다. 올린 사람만 목록, 원본, 삭제에 접근할 수 있습니다. 공개 기록 화면에는 나오지 않습니다. |
| 제목 | 앞뒤 공백을 제거한 뒤 1~100자 |
| 메모 | 선택 입력, 최대 1,000자 |
| 파일 | 자료마다 정확히 1개. PNG·JPG는 최대 5MB, MP4는 최대 30MB |
| 허용하지 않는 것 | 위 세 형식 이외의 파일(GIF, SVG, WebP, MOV 등), 크기 초과 파일, 비어 있는 파일, 확장자만 바꾼 가짜 파일 |
| 로그인 | 기존 쿠키 로그인을 그대로 사용합니다. 로그인하지 않으면 모든 자료 기능을 쓸 수 없습니다. |

- MB는 1MB = 1,048,576바이트로 계산합니다. (5MB = 5,242,880바이트, 30MB = 31,457,280바이트)

### 12.4 필요한 화면

- **학습 자료함 화면 (`/materials`)**: 등록 폼(제목, 메모, 파일 선택, 업로드 버튼), 내 자료 목록, 이미지·영상 필터, 원본 보기와 삭제 버튼.
- 화면의 모양은 이미 만들어져 있습니다. (Figma 시안 기준, 현재는 예시 목록이며 기능 연결 전)
- 컴퓨터에서는 등록 폼과 목록을 나란히, 작은 화면에서는 위아래로 보여줍니다.
- AI 학습 도우미 영역은 12.8의 AI 요약이 연결되기 전까지 "연결 예정"을 유지하고, 연결 뒤에는 "사용 중/설정 필요" 상태를 보여줍니다.

### 12.5 이번 확장에서 만들지 않는 것

- 자료 수정(제목·메모 변경, 파일 교체), 자료 검색
- 다른 사용자와 자료 공유, 공개 기록과의 연결, 댓글·좋아요·신고
- 여러 파일을 한 번에 올리기, 끌어다 놓기(드래그 앤 드롭) 업로드
- 이미지 축소본(썸네일) 만들기, 영상 변환
- 사용자별 저장 용량 제한, 파일 백업
- AI 이미지 분석 (OpenAI 연결) → **요약 기능만 12.8에서 추가로 만듭니다.** 복습 질문 만들기, 영상 소리 분석 등은 계속 만들지 않습니다.

### 12.6 현재 기술 기준

- 화면은 React, 서버는 FastAPI, 데이터베이스는 Supabase PostgreSQL을 기준으로 합니다. 실제 코드는 이미 Supabase PostgreSQL에 연결되어 있습니다. (자동 테스트만 임시 SQLite를 사용)
- 10장의 "개발은 SQLite" 표현은 첫 버전을 계획할 당시의 내용입니다. 이 확장은 PostgreSQL에서 먼저 동작해야 하고, 자동 테스트는 SQLite에서도 통과해야 합니다.
- 파일은 서버의 `backend/uploads` 폴더에 저장하고, 제목·메모·파일 정보는 Supabase의 별도 `materials` 표에 저장합니다.

### 12.7 확장 기능이 완성된 것으로 보는 기준

- 로그인한 사용자가 자료를 올리면 목록에 나타나고, 새로고침하거나 서버를 다시 켜도 그대로 있습니다.
- 원본 보기가 되고, 삭제하면 목록과 파일이 모두 사라집니다.
- 다른 사용자는 내 자료의 목록, 원본, 삭제 어느 것에도 접근할 수 없습니다.
- 허용하지 않는 파일과 입력은 이유를 알려주며 거절하고, 실패한 업로드는 아무것도 남기지 않습니다.
- 기존 로그인·대시보드·기록 화면은 그대로 동작합니다.

### 12.8 AI 요약 (확장, 2026-10-27 추가)

학습 자료함에 저장한 이미지·영상을 OpenAI로 자동 요약하고, 요약을 자료와 함께 저장합니다. 설계는 `sdd-ai-summary.md`를 따릅니다.

| 항목 | 규칙 |
| --- | --- |
| 언제 | 자료를 저장한 직후 자동으로. 저장은 AI 성공 여부와 무관하게 먼저 끝납니다. |
| 무엇을 | 이미지는 1장, 영상은 길이에 맞춰 뽑은 장면 최대 8장을 요약합니다. 영상의 소리는 분석하지 않습니다. |
| 결과 | 주제 한 문장과 핵심 3~5개 항목, 600자 이내의 한국어 평문. 자료와 함께 저장됩니다. |
| 선택 | 등록할 때 "AI 요약하기"를 끌 수 있습니다. 기본은 켜짐입니다. |
| 안내 | 요약을 위해 이미지가 OpenAI로 전송된다는 사실과 OpenAI의 데이터 취급(학습에 사용하지 않음, 오남용 점검용 최대 30일 보관)을 화면에 항상 알립니다. |
| 한도 | 사용자 1명당 하루 30회 (한국 날짜 기준). 자료를 지워도 횟수는 돌아오지 않습니다. |
| 실패 | 실패해도 자료는 남고, 이유를 알려주며 "다시 분석"을 누를 수 있습니다. |
| 기존 자료 | 이미 있는 자료는 요약이 없는 상태이며, 자료마다 "AI 요약 만들기"를 눌러 만듭니다. |
| 키가 없을 때 | AI 기능만 꺼집니다. 등록·목록·원본 보기·삭제는 그대로 동작합니다. |
| 접근 | 요약은 자료와 같이 올린 사람만 볼 수 있습니다. |
