## Supabase(PostgreSQL) 전환 준비

### 완료한 것
- `DATABASE_URL`을 필수로 변경했습니다. 없거나 형식이 틀리면 SQLite로 연결하지 않고 확인할 항목을 안내한 뒤 멈춥니다.
- `postgresql://` 주소를 psycopg 드라이버 형식으로 자동 변환합니다. 연결 풀 사전 점검(pool_pre_ping)과 연결 제한 시간(10초)을 추가했습니다.
- Alembic은 SQLite일 때만 배치 모드를 쓰고, 연결 실패 시 비밀번호가 나오지 않는 안내를 출력합니다.
- `psycopg[binary]`를 설치하고 `requirements.txt`에 기록했습니다. `.env.example`을 Supabase Session pooler 기준으로 다시 썼습니다.
- 기존 SQLite 파일과 데이터는 그대로 두었습니다. 데이터 이전은 하지 않습니다.
- 자동 테스트 서버 65개 통과 (테스트는 임시 SQLite 사용).

### 확인하지 못한 것

## 학습 자료함 M3. 업로드 API

### 완료한 것
- `POST /api/materials` (제목 `title`, 메모 `memo`, 파일 `file`)를 만들었습니다. 성공하면 201과 자료 정보를 돌려주고, 응답에는 저장 파일 이름·서버 경로·사용자 번호를 넣지 않습니다.
- 새 파일: `backend/app/storage.py`(파일 저장·검사·삭제), `backend/app/schemas/material.py`(제목·메모 검사와 응답), `backend/app/routers/materials.py`. `main.py`에 주소를 등록했습니다.
- 패키지 `python-multipart==0.0.32`를 설치하고 `requirements.txt`에 기록했습니다.
- 로그인(`get_current_user`)을 먼저 확인한 뒤에 파일을 받습니다. 로그인하지 않으면 401이고 파일을 받지 않습니다.
- 검사: 제목 공백 제거 후 1~100자, 메모 최대 1,000자(비면 비움), 파일 정확히 1개, 확장자 + 브라우저가 알린 형식 + 파일 앞부분 표식이 모두 PNG·JPG·MP4와 맞는지, PNG·JPG 5MB·MP4 30MB(읽으면서 직접 셈), 빈 파일 거절, MOV를 .mp4로 바꾼 파일 거절, NUL 문자 거절(PostgreSQL 오류 방지). 요청 전체가 약 31MB를 넘으면 받기 전에 거절합니다.
- 파일은 `backend/uploads/materials`에 서버가 만든 임의의 이름으로 저장합니다. 사용자의 파일 이름은 표시용으로만 저장하고 경로 구분자를 지웁니다.
- 실패하면 임시·최종 파일과 데이터베이스 변경을 모두 되돌립니다. (데이터베이스 오류, 파일 이름 바꾸기 실패, 폴더 만들기 실패를 각각 시험)
- 서버 테스트 132개 통과 (기존 78개 + 새 54개). 5MB 한도를 일부러 바꿔 경계 테스트가 실패하는 것도 확인했습니다. 테스트는 임시 폴더만 쓰며 실제 `backend/uploads`는 만들어지지 않았습니다.
- 백엔드(8000)를 새 코드로 다시 켰습니다. 로그인 없이 호출하면 401이 나오는 것을 확인했습니다.

### 확인하지 못한 것
- 실제 Supabase에 업로드해서 `materials` 표에 행이 생기는지 (M2의 `alembic upgrade head` 실행 후 사용자 확인 필요). 실제 데이터를 쓰게 되므로 제가 시험 업로드를 하지 않았습니다.
- 자동 테스트는 SQLite를 썼습니다.

### 메모
- 저장 순서를 plan 9.2에서 바꿨습니다: 데이터베이스에 넣기(flush) → 파일을 최종 이름으로 바꾸기 → 확정(commit). 중간에 멈춰도 "파일 없는 자료 정보"가 생기지 않게 하기 위해서입니다.
- 파일을 보낸 쪽이 Content-Length를 거짓으로 적거나 조각으로 나눠 보내면 서버가 임시로 받을 수는 있으나, 최종 저장 전에 파일 크기를 직접 세어 한도를 넘으면 거절하고 지웁니다.

## 학습 자료함 M4. 조회·삭제 API

### 완료한 것
- `GET /api/materials`: 내 자료만 최신 등록순(같은 시각이면 나중에 등록한 것이 먼저)으로 돌려주고, `kind=image|video`로 거를 수 있습니다. 필터와 관계없이 내 전체 기준의 종류별 개수 `counts`(`all`, `image`, `video`)를 함께 보냅니다. 알 수 없는 `kind`는 422(`field: kind`)입니다.
- `GET /api/materials/{id}/file`: 본인 자료의 원본을 전달합니다. 저장된 형식(`image/png`, `image/jpeg`, `video/mp4`)으로만 알리고, `X-Content-Type-Options: nosniff`, `Cache-Control: private, no-store`를 붙입니다. 영상 탐색을 위한 Range 요청(206)이 동작합니다.
- `DELETE /api/materials/{id}`: 본인 자료만 지웁니다. 자료 정보를 먼저 지워 확정한 뒤 파일을 지우고, 성공하면 204입니다.
- 다른 사람의 자료와 없는 자료는 상태 코드와 본문이 똑같은 404 "자료를 찾을 수 없습니다."입니다. (원본, 삭제 모두)
- 서버에 저장된 파일 이름이 서버가 만든 형식(`32자리 16진수.png|jpg|mp4`)이 아니면 파일을 열거나 지우지 않습니다. (데이터가 조작되어도 폴더 밖 파일을 건드리지 않음)
- 파일이 이미 없어도 삭제는 성공합니다. 파일을 지우지 못하면 기록만 남기고 사용자에게는 삭제된 것으로 보입니다. 데이터베이스에서 지우지 못하면 500과 안내를 주고 자료와 파일을 그대로 둡니다.
- 공통 오류 처리(`app/errors.py`)를 한 줄 고쳤습니다. 주소의 조건(`?kind=`)이나 번호가 틀렸을 때 `field`가 `query`·`path`로 나오던 것을 입력 이름(`kind`)으로 나오게 했습니다. 기존 로그인·계정 오류에는 영향이 없습니다.
- 서버 테스트 159개 통과 (기존 132개 + 새 27개). 소유자 조건을 일부러 빼면 격리 테스트가 실패하는 것도 확인한 뒤 되돌렸습니다.
